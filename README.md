# Academic Research Assistant

This Streamlit application is a retrieval-augmented generation (RAG) assistant for searching the bundled academic-paper dataset. It combines FAISS semantic retrieval, publication-year filtering, configurable top-k selection, recency-aware reranking, and Gemini answer generation.

## Data flow

```text
CSV dataset -> preprocessing -> LangChain documents -> embeddings -> FAISS index
-> user query -> semantic search -> year filtering -> combined ranking
-> top-k selection -> newest-first sorting -> RAG context -> Gemini answer
-> Streamlit answer and retrieved-paper list
```

## Dataset and preprocessing

The source dataset is `data/academic_papers.csv`. Each row represents one paper. The loader uses the title, abstract, full text, and keywords to create a LangChain `Document` while retaining paper ID, title, integer publication year, and discipline metadata.

Preprocessing normalizes missing values and surrounding/repeated whitespace without removing technical punctuation or scientific terminology. Invalid or missing required paper IDs/titles and invalid publication years raise clear errors. The embedding provider tokenizes the document text internally. The full text is not arbitrarily word-split, because the source papers are designed to fit the existing embedding provider while preserving paper-level meaning.

## Retrieval and ranking

FAISS retrieves every indexed document, rather than a hardcoded candidate count. L2 distances are normalized to a 0–1 semantic score for ranking. Inner-product similarities, when used by an index, are normalized consistently across candidates. The selected papers are ranked using:

```text
combined score = (0.8 * semantic score) + (0.2 * recency score)
```

Recency is normalized within the eligible dataset's actual publication-year range. Missing or malformed years receive a recency score of zero. Stage 1 applies the year filter and selects the best `k` distinct paper IDs. Stage 2 sorts those selected papers by publication year, descending; combined score and paper ID provide deterministic tie-breaking.

If fewer distinct papers satisfy the filters than requested, the result reports the actual count rather than inventing entries.

## RAG generation

Gemini chat generation uses the `gemini-3.5-flash-lite` model. The prompt is restricted to the retrieved paper context and requires unsupported claims and citations to be avoided. The retrieved-paper list is rendered by Streamlit from structured retriever results, not generated by the language model.

`AI_PROVIDER` controls embedding provider selection only. `gemini` uses Gemini embeddings, `openai` uses `text-embedding-3-small`, and `auto` uses OpenAI when `OPENAI_API_KEY` is configured and Gemini otherwise.

## Setup

Python 3.11 or 3.12 is required.

```bash
uv sync
```

Create a `.env` file in the repository root:

```dotenv
AI_PROVIDER=gemini
GOOGLE_API_KEY=your-google-api-key
```

For OpenAI embeddings, answer generation remains Gemini-based:

```dotenv
AI_PROVIDER=openai
OPENAI_API_KEY=your-openai-api-key
GOOGLE_API_KEY=your-google-api-key
```

## Run the application

```bash
uv run streamlit run src/project/app.py
```

Enter a question, minimum publication year, and number of research papers to retrieve. The result shows the Gemini answer and a separate newest-first retrieved-paper list.

## Build or rebuild the FAISS index

Build the index from `data/academic_papers.csv`:

```bash
uv run python -c "from project.vectorstore import build_vectorstore; build_vectorstore()"
```

Rebuild after changing the CSV, preprocessing, or embedding provider/model. The index is stored at `data/faiss_index/` using a repository-root-relative path.

FAISS deserialization is disabled for untrusted pickle files. An existing index with metadata for an incompatible provider/model is rejected and must be rebuilt. Only a trusted, locally generated index should be used.

## Tests

Run the pytest suite:

```bash
uv run pytest -q
```

Tests cover top-k selection, year filtering, newest-first ordering, combined ranking, invalid inputs, duplicate paper IDs, insufficient matches, and RAG context forwarding. Tests mock external models and FAISS and do not consume API credits.

`main.py` is a small diagnostic utility that loads the academic CSV and reports the configured embedding provider; it does not use `data/documents.json`.

## Known limitations

- Retrieval is based on the bundled synthetic dataset and does not perform live academic literature search.
- Long-document handling is delegated to the embedding provider; no automatic chunking is currently applied.
- Gemini chat/API availability depends on the configured API key and account.
- Index compatibility is guaranteed only when rebuilding after provider/model configuration changes.
