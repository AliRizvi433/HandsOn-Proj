# Academic Research Assistant

A Streamlit-based retrieval-augmented generation (RAG) application for asking questions about the academic papers bundled with this repository.

## Assessment problem

The project addresses an academic research-assistant workflow: preprocess structured research-paper records, tokenize their content for embedding, store the embeddings in FAISS, retrieve the requested number of distinct papers using semantic relevance and publication recency, and present the selected papers newest first while generating a grounded answer.

The application:

- Loads papers from `data/academic_papers.csv`.
- Uses Gemini or OpenAI embeddings.
- Searches a local FAISS vector index.
- Optionally filters results by minimum publication year.
- Combines semantic relevance with recency.
- Uses Gemini to generate an answer from the retrieved paper context.

The paper list displayed by the application comes from the retriever, while the generated answer is produced separately by the language model.

## Requirements

- Python 3.11 or 3.12
- [uv](https://docs.astral.sh/uv/)
- A Google Gemini API key
- An OpenAI API key only if OpenAI embeddings are selected

## Installation

Clone the repository, open a terminal in the project directory, and install the locked dependencies:

```bash
uv sync
```

Create a `.env` file in the repository root.

### Gemini embeddings

```dotenv
AI_PROVIDER=gemini
GOOGLE_API_KEY=your-google-api-key
```

### OpenAI embeddings with Gemini answers

```dotenv
AI_PROVIDER=openai
OPENAI_API_KEY=your-openai-api-key
GOOGLE_API_KEY=your-google-api-key
```

If `AI_PROVIDER` is omitted, the application selects OpenAI when `OPENAI_API_KEY` is available; otherwise it selects Gemini.

Do not commit `.env` or API keys to source control.

## Vector index

The FAISS index is stored in `data/faiss_index/`. A valid index must contain `index.faiss`, `index.pkl`, and `index_metadata.json`. Rebuild it when the CSV data, embedding provider, or embedding model changes:

```bash
uv run python -c "from project.vectorstore import build_vectorstore; build_vectorstore()"
```

The command reads `data/academic_papers.csv` and writes the generated index files to `data/faiss_index/`. Older indexes that do not contain `index_metadata.json` cannot be verified and must be rebuilt before use.

Loading uses LangChain's `allow_dangerous_deserialization=True` because `index.pkl` contains serialized local document data. This is safe only for an index generated by this repository from trusted local files; never use the setting to load an index downloaded from an untrusted source.

## Run the application

```bash
uv run streamlit run src/project/app.py
```

In the browser interface:

1. Enter a question about the bundled papers.
2. Optionally enable **Filter by minimum publication year** and select a year.
3. Select the number of papers to retrieve.
4. Click **Search**.

The page shows the generated answer, the number of matching papers, and the retrieved papers with their title, year, discipline, paper ID, and normalized ranking score. The score is relative to the current candidate set, not a probability or confidence value.

## Run tests

```bash
uv run pytest -q
```

Most tests mock external model calls, while integration tests build and load a temporary real FAISS index with deterministic local embeddings. The suite does not require API credits.

## Diagnostic entry point

To load the CSV and print the paper count and selected embedding provider:

```bash
uv run python main.py
```

This command still requires the provider's corresponding API key because provider selection validates the configuration.

## RAG data flow and retrieval

```text
structured CSV paper
  -> whitespace normalization and field validation
  -> LangChain Document (title, abstract, full text, keywords + metadata)
  -> provider embeddings
  -> FAISS index (index.faiss, index.pkl, index_metadata.json)
  -> query embedding and full candidate search
  -> optional year filtering and paper-ID deduplication
  -> 80/20 semantic-recency ranking
  -> top-k distinct papers
  -> newest-first presentation and Gemini RAG answer
```

1. Each CSV row becomes one LangChain `Document`. The page content preserves the title, abstract, full text, and keywords; metadata preserves the paper ID, publication year, title, and discipline.
2. Whitespace is normalized before embedding. A conservative token estimate is available for diagnostics, while the selected embedding provider performs the authoritative tokenization internally. Documents are not artificially rejected because of an approximate 8,000-token threshold, and no chunks are created that could be counted as separate papers.
3. The selected Gemini or OpenAI embedding provider creates vectors, and `build_vectorstore()` saves them in FAISS with provider/model metadata.
4. FAISS returns candidates for the query. Invalid years and duplicate paper IDs are excluded or deduplicated.
5. Candidates are optionally filtered by the minimum publication year.
6. Candidates are ranked with:

   ```text
   combined score = (0.8 * semantic score) + (0.2 * recency score)
   ```

7. Stage one selects the best `k` distinct papers using the combined score. If fewer eligible papers exist, the application returns the available count.
8. Stage two sorts the selected papers by publication year descending, with score and paper ID tie-breakers. This newest-first presentation makes recency clear without changing which papers won the relevance ranking.
9. The selected paper content is passed to Gemini as the RAG context. The retrieved-paper list is rendered separately from structured results.

FAISS L2 distances are min-max normalized and inverted so larger semantic scores are better. Inner-product similarities are min-max normalized directly. If all candidates have the same raw score, each receives `1.0`; recency and stable paper-ID tie-breakers keep the result deterministic.

These normalized scores describe relative ordering within one search and must not be interpreted as probabilities, calibrated confidence, or cross-query similarity values.

If fewer than `k` papers match, the application returns the available matches rather than inventing additional results.

## Project structure

```text
data/
  academic_papers.csv       # Source paper dataset
  faiss_index/              # Local FAISS index and metadata
src/project/
  app.py                    # Streamlit user interface
  config.py                 # Environment and path configuration
  embeddings.py             # Gemini/OpenAI embedding selection
  loader.py                 # CSV loading and document preparation
  rag.py                    # Gemini answer generation
  retriever.py              # FAISS search, filtering, and ranking
  vectorstore.py            # FAISS index creation and loading
main.py                     # Configuration/data diagnostic
test_*.py                   # Automated tests
```

## Limitations

- Search is limited to the bundled dataset; it is not a live academic search engine.
- The token estimate is conservative and provider-independent; exact tokenization remains inside the embedding provider.
- No automatic document chunking is performed, so unusually large papers remain subject to the selected provider's limits.
- Answer generation requires a working Gemini API configuration.
- Rebuild the FAISS index after changing the embedding provider or model.
